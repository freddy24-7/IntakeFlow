Tech Stack

What IntakeFlow is built with, and what each part does in it.

Application

Python 3.12 and FastAPI

The web application and the worker, async throughout.

PostgreSQL, SQLAlchemy 2 and Alembic

Documents, extractions, review decisions, the audit log and the workflow's saved state.

Pydantic 2

The schemas the model must answer in, and the application's settings.

Jinja2 and HTMX

Server-rendered pages. No single-page framework.

LangChain and LangGraph

Structured output

LangChain turns a Pydantic schema into a strict request to the model and parses the answer back. Code then checks the model's work against the text as printed.

Model and embedding wrappers

Azure OpenAI chat and embedding models through LangChain, with sign-in by identity instead of keys.

Retriever

The contract search exposed through LangChain's retriever interface.

LangGraph workflow

The document pipeline as a graph: a branch per document type, retries on the calls to Azure, and state saved in PostgreSQL after every step so a run can resume.

Azure

Document Intelligence

Reads every page, including scans, and returns invoice fields with a confidence.

Azure OpenAI

gpt-4.1-mini classifies. gpt-4.1 extracts and answers. text-embedding-3-large embeds contract clauses.

AI Search

Hybrid search over contract clauses: keywords and vectors combined.

Container Apps

The web application and the worker, both scaling to zero. Microsoft sign-in in front.

Queue and Blob Storage

A queue between upload and processing, so a document survives a crash. Uploaded files in blobs.

Database for PostgreSQL

The managed database behind the application.

Managed identity and Key Vault

The application signs in to every service without keys. The one secret, the database URL, is in Key Vault.

Application Insights

Traces and logs through OpenTelemetry, without document content.

Bicep and Container Registry

The whole environment as code, with one command to create it and one to remove it.

Quality

pytest and Playwright

Unit, integration and browser tests. Azure is replaced by fakes behind the same interfaces, so the tests need no cloud.

ruff and mypy --strict

Lint, formatting and strict type checking on every push.

GitHub Actions

CI on every push. Deployment is started by hand and signs in to Azure without a stored secret.

Evaluation scripts

Accuracy, routing and question answering are measured against labelled synthetic documents, and the reports are in the repository.

Measured results, design rules and what was learned are in the README of the repository: github.com/freddy24-7/IntakeFlow.
