How to use IntakeFlow

What kind of app this is

IntakeFlow is a demo of a document intake pipeline for an accounts payable department. It takes supplier invoices, credit notes and contracts as PDF, turns them into checked, structured data, and decides for each document whether it can be approved automatically or needs a person.

It is a portfolio project, not a product. The company it is built around, Noordzee Logistiek B.V., is fictional, and every document in it is generated. There is no real customer data here.

The interface is in Dutch, because its imagined users are Dutch finance staff. This page and the Tech Stack page are in English for visitors.

What happens to a document

  1. It is read. Every page goes through Azure Document Intelligence, so scanned pages work too.
  2. It is classified as an invoice, a credit note, a contract or other mail.
  3. An invoice is extracted and checked. A language model extracts the fields, and plain code checks them: do the totals add up, is the IBAN valid, does the purchase order exist and match, has this invoice been seen before.
  4. It is routed. If every check passes, the invoice is approved automatically and booked. If anything fails or is in doubt, it goes to a person, with the reasons listed.
  5. A contract is indexed clause by clause, so questions about it can be answered with the source.

Try it

Start by choosing a role on the start page. There is no password. You can switch at any time with "Andere rol".

Financieel medewerker

Upload and review

  1. Open Uploaden and choose one or more PDFs. Hold Cmd or Ctrl to select several.
  2. Open Beoordelen. Documents that need a person appear here, each with the reason. The list refreshes by itself.
  3. Click Beoordelen on a document to see the page next to the extracted fields.
  4. Correct a field if needed, use Controleren to see which checks still fail, then approve or reject.
Contractbeheerder

Ask the contract archive

  1. Open Contracten.
  2. Ask a question that names the supplier, for example: "Wat is de opzegtermijn in het contract met Arens Software B.V.?"
  3. The answer comes with the contract, clause and page it was found in.
  4. If the contracts do not contain the answer, you get "Niet gevonden in de documenten".
Teamleider

See the numbers

  1. Open Dashboard.
  2. See how many documents came in, the share approved automatically, the share a person had to correct, the time to a result and the cost per document.
  3. The accuracy table at the bottom comes from the evaluation on labelled test documents, not from the documents uploaded here.

Good to know

  • Sample documents are in the project's repository. They are generated by a script, and the folder data/synthetic/documents holds 200 of them after running it.
  • Processing takes a moment. One worker handles one document at a time and starts from zero when idle, so the first document can take a minute or two.
  • Clean invoices do not show up under Beoordelen. They are approved automatically. The dashboard counts them.
  • Uploading the same invoice twice gets the second copy flagged as a duplicate. That is the system working.
  • The model never approves on its own. Approval needs every check in plain code to pass, and a person can always overrule the checks, never the other way round.
